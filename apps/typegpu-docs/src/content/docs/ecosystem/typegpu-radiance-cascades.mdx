`@typegpu/radiance-cascades` computes lighting for 2D scenes. Provide GPU functions
for the scene's shapes and emitted light, then sample the resulting texture in
your rendering shader. The built-in tracer treats surfaces as opaque; surface
reflection and additional light bounces require application logic.

## Basic usage

<div class="my-4 flex justify-center">
  <Image src={basicPreview} alt="Two glowing shapes illuminating a 2D scene" class="w-full max-w-[20rem] rounded-md" />
</div>

```ts twoslash
import * as rc from '@typegpu/radiance-cascades';
import * as sdf from '@typegpu/sdf';
import { tgpu, d, std } from 'typegpu';

const root = await tgpu.init();
const previewSize = { width: 512, height: 512 };

const sceneSdf = tgpu.fn([d.vec2f], d.f32)((uv) => {
  'use gpu';
  const circle = sdf.sdDisk(uv - d.vec2f(0.5), 0.18);
  const wall = sdf.sdRoundedBox2d(uv - d.vec2f(0.5, 0.82), d.vec2f(0.42, 0.03), 0.01);
  return sdf.opUnion(circle, wall);
});

const emission = tgpu.fn([d.vec2f], d.vec3f)((uv) => {
  'use gpu';
  return std.mix(d.vec3f(1, 0.82, 0.5), d.vec3f(0.28, 0.52, 1), uv.x);
});

const runner = rc.createRadianceCascades({
  root,
  size: previewSize,
  sdfResolution: { width: 1024, height: 1024 },
  sdf: sceneSdf,
  emission,
});

runner.run();

const radianceView = runner.output.createView(d.texture2d());
const sampler = root.createSampler({ magFilter: 'linear', minFilter: 'linear' });

const renderPreview = tgpu.fn([d.vec2f], d.vec4f)((uv) => {
  'use gpu';
  const dist = sceneSdf(uv);
  const edge = std.max(std.fwidth(dist), 0.001);
  const surface = 1 - std.smoothstep(-edge, edge, dist);
  const radiance = std.textureSampleLevel(radianceView.$, sampler.$, uv, 0).xyz;

  const bg = std.mix(d.vec3f(0.04, 0.05, 0.07), d.vec3f(0.11, 0.15, 0.22), uv.y);
  const lit = bg + radiance * 1.55;
  const color = std.mix(lit, emission(uv), surface);

  return d.vec4f(std.min(color, d.vec3f(1)), 1);
});
```

## Scene inputs

The scene callbacks receive coordinates from 0 to 1 on each axis.

| Input | Meaning |
| --- | --- |
| `size` | Lighting texture dimensions in pixels; these can be smaller than the canvas |
| `sdf(uv)` | Distance to the nearest surface: positive outside, zero on the surface, negative inside |
| `emission(uv)` | Emitted light in linear RGB, not material color; zero for a non-emitting obstacle, with values above 1 allowed |
| `sdfResolution` | Dimensions of the distance texture; for an analytic function, use the resolution at which you want to resolve surface detail |

Measure distances relative to the shorter side of the scene. For a 1024 × 512
scene, a distance of 10 pixels is `10 / 512`. A generated distance texture should
use the same convention. `sdfResolution` sets the minimum hit tolerance and step
size; it does not allocate a distance texture.

For rectangular scenes, the scene aspect defaults to the output texture's width
divided by its height.
Set `renderAspect` if your lighting texture has a different aspect from the scene.
For example, a square lighting texture covering a 1024 × 512 scene needs
`renderAspect: 2`.

## Updating lighting

Create the runner once and call `run()` after updating the buffers or textures
read by its scene callbacks. Each call submits a lighting update. When its size
or configuration changes, call `destroy()` and create a new runner.

To prepare the GPU pipelines before the first update, use `await runner.initAsync()`.
This is optional; `initSync()` provides a synchronous alternative.

Pass a command encoder to `run(encoder)` to record the update without submitting
it. Submit that encoder after recording the rest of your frame.

If a callback uses an explicit bind group layout, attach its resources with
`runner.with(bindGroup)` and use the returned runner. Captured TypeGPU views,
samplers and accessors are bound automatically.

### Output textures

`runner.output` is an `rgba16float` texture created with storage and sampled usage,
unless you supply an `output` texture or storage view. The runner destroys its own
output when you call `destroy()`; caller-supplied output remains yours to release.

```ts twoslash
import * as rc from '@typegpu/radiance-cascades';
import { d, type TgpuRoot } from 'typegpu';

declare const root: TgpuRoot;
declare const width: number, height: number;
declare const sdfResolution: { width: number; height: number };
declare const sceneSdf: (uv: d.v2f) => number;
declare const emission: (uv: d.v2f) => d.v3f;
// ---cut---
const output = root
  .createTexture({
    size: [width, height],
    format: 'rgba16float',
  })
  .$usage('storage', 'sampled');

const runner = rc.createRadianceCascades({
  root,
  output,
  sdfResolution,
  sdf: sceneSdf,
  emission,
});
```

When a storage view cannot provide its size, pass `size` explicitly alongside `output`.

## Image-based scenes

For scenes drawn into an image, [`@typegpu/sdf`](/TypeGPU/ecosystem/typegpu-sdf/)
can generate the distance texture. In this example, alpha marks solid pixels and
RGB stores their emitted light.

<div class="my-4 flex justify-center">
  <Image src={generatedSdfPreview} alt="Lighting computed from a drawn image" class="w-full max-w-[24rem] rounded-md" />
</div>

```ts twoslash
import * as rc from '@typegpu/radiance-cascades';
import * as sdf from '@typegpu/sdf';
import { tgpu, d, std } from 'typegpu';

const root = await tgpu.init();
const floodSize = { width: 2048, height: 2048 };
const previewSize = { width: 512, height: 512 };

const sourceTexture = root
  .createTexture({
    size: [floodSize.width, floodSize.height],
    format: 'rgba8unorm',
  })
  .$usage('storage', 'sampled');

// Fill sourceTexture with the scene before running the lighting update
const sourceView = sourceTexture.createView();

const floodRunner = sdf.createJumpFlood({
  root,
  size: floodSize,

  classify: (coord) => {
    'use gpu';
    return std.textureLoad(sourceView.$, coord, 0).w > 0.5;
  },

  getSdf: (_coord, size, signedDist) => {
    'use gpu';
    return signedDist / d.f32(std.min(size.x, size.y));
  },

  getColor: (_coord, _size, _signedDist, insidePx) => {
    'use gpu';
    const source = std.textureLoad(sourceView.$, insidePx, 0);
    return d.vec4f(source.xyz, 1);
  },
});

const floodSdfView = floodRunner.sdfOutput.createView();
const floodColorView = floodRunner.colorOutput.createView();
const sampler = root.createSampler({ magFilter: 'linear', minFilter: 'linear' });

const runner = rc.createRadianceCascades({
  root,
  size: previewSize,
  sdfResolution: floodSize,

  sdf: (uv) => {
    'use gpu';
    return std.textureSampleLevel(floodSdfView.$, sampler.$, uv, 0).x;
  },

  emission: (uv) => {
    'use gpu';
    return std.textureSampleLevel(floodColorView.$, sampler.$, uv, 0).xyz;
  },
});

function updateLighting() {
  floodRunner.run();
  runner.run();
}

updateLighting();
```

Call `updateLighting()` again after editing the source image.

## Quality and cost

`size` controls lighting resolution. A smaller texture costs less, but resolves
less spatial detail. `baseStoredRayDim` controls how many light directions are
sampled independently of that resolution:

| `baseStoredRayDim` | Directions at the finest lighting resolution | Use |
| --- | --- | --- |
| `1` (default) | 4 | Lower-cost setting |
| `2` | 16 | More direction samples |
| `4` | 64 | More direction samples at a higher cost |

More directions can help with small lights and thin obstacles. The improvement
depends on the scene; compare the result before increasing this setting.

`mergeMode` offers a separate quality/cost choice:

- `'hardware'` (default) uses the faster interpolation path.
- `'bilinear-fix'` performs additional visibility checks, which can reduce light
  leaking around obstacles at a higher cost.

## Advanced usage

### Tracing controls

These settings adjust how the built-in tracer finds surfaces:

| Option | Default | Effect |
| --- | --- | --- |
| `maxRaySteps` | `64` | Maximum steps along each ray; raising it permits more tracing work |
| `stepSafety` | `1` | Step multiplier in `(0, 1]`; smaller values take shorter steps and may need a larger step budget |
| `erodeBiasProbes` | `1` | Increasing this makes obstacles effectively thinner, which can reduce self-shadowing but lose thin features |
| `epsProbes` | `0.25` | Surface hit tolerance; increasing it accepts hits farther from the surface |
| `minStepProbes` | `0.125` | Minimum step length; increasing it reduces work near surfaces but can skip thin features |

The three distances ending in `Probes` use lighting-sample spacing as their unit:
`1` is the distance between neighboring samples at the finest lighting
resolution. The hit tolerance and minimum step are also limited by
`sdfResolution`, so reducing these settings below the source texture's detail
level has no effect.

### Custom tracing

Use `rayMarch` when you need different light transport, such as attenuation or
partial transmission. This callback replaces the built-in tracer in both merge
modes. It receives a ray and the segment to trace:

```ts twoslash
import * as rc from '@typegpu/radiance-cascades';
import { d } from 'typegpu';

declare const rayMarch: NonNullable<Parameters<typeof rc.createRadianceCascades>[0]['rayMarch']>;
declare const origin: d.v2f, direction: d.v2f;
declare const startT: number, endT: number, eps: number, minStep: number, bias: number;
// ---cut---
rayMarch(origin, direction, startT, endT, eps, minStep, bias);
```

Trace positions with `origin + direction * t`, for `t` between `startT` and `endT`.
The distances use the same scene units as `sdf`. The runner supplies `eps`,
`minStep` and `bias` from the tracing controls above; your callback decides how to
use them. `maxRaySteps` and `stepSafety` control only the built-in tracer.

Return `rc.RayMarchResult({ color, transmittance })`:

- `color` is the linear RGB light accumulated over that segment.
- `transmittance` is the fraction of light that passes through the segment:
  `1` for fully transparent, `0` for fully opaque, or a value between them.

### Layout and tracing utilities

These exports are for custom tracing and inspecting the internal lighting layout:

| Export | Purpose |
| --- | --- |
| `defaultRayMarch` | The built-in ray marcher used by the runner |
| `RayMarchResult` | Return struct for custom ray marchers |
| `getCascadeDim` | Returns `[width, height, cascadeCount]` for the internal cascade layout |
| `getCascadeInfo` | Base probe grid, cascade count, per-layer probes and intervals |
| `sdfSlot`, `emissionSlot`, `rayMarchSlot` | Scene functions used by the built-in tracer |
| `maxRayStepsAccess`, `rayMarchStepSafetyAccess` | Built-in tracing controls |

The [package source](https://github.com/software-mansion/TypeGPU/tree/main/packages/typegpu-radiance-cascades/src) contains the implementation.
