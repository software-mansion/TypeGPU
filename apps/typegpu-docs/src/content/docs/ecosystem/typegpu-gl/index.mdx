title: "@typegpu/gl"

`@typegpu/gl` lets TypeGPU generate GLSL and provides an experimental WebGL 2 backend for a subset of TypeGPU's render API.
It is useful when an application needs to run a render effect in browsers without WebGPU, or when TypeGPU shader functions need to be integrated into an existing WebGL renderer.

:::caution[Experimental]
The WebGL 2 backend does not implement the full TypeGPU API. It supports render pipelines (with vertex, index and uniform buffers, depth and stencil testing, blending and multiple render targets), constants, helper functions, and a focused subset of 2D textures. Compute shaders, storage buffers, bind groups, and other WebGPU-only features are not supported, and throw a `WebGLFallbackUnsupportedError`.
:::

## Your first fallback

Use `initWithGLFallback` in place of `tgpu.init` to try WebGPU first and fall back to WebGL 2 if WebGPU is unavailable or initialization fails.

```ts twoslash
import { initWithGLFallback } from '@typegpu/gl';

const root = await initWithGLFallback();
```

The returned root exposes the common TypeGPU API, so a supported render pipeline does not need separate WebGPU and WebGL implementations.
Let's create a triangle whose color varies with its UV coordinates.

```ts twoslash
import { tgpu, d } from 'typegpu';
import { initWithGLFallback } from '@typegpu/gl';

const root = await initWithGLFallback();
// ---cut---
const positions = tgpu.const(d.arrayOf(d.vec2f, 3), [
  d.vec2f(0, 0.5),
  d.vec2f(-0.5, -0.5),
  d.vec2f(0.5, -0.5),
]);

const uvs = tgpu.const(d.arrayOf(d.vec2f, 3), [
  d.vec2f(0.5, 1),
  d.vec2f(0, 0),
  d.vec2f(1, 0),
]);

const pipeline = root.createRenderPipeline({
  vertex: ({ $vertexIndex: index }) => {
    'use gpu';
    return {
      $position: d.vec4f(positions.$[index], 0, 1),
      uv: uvs.$[index],
    };
  },
  fragment: ({ uv }) => {
    'use gpu';
    return d.vec4f(uv, 0.5, 1);
  },
});
```

The vertex data is stored in TypeGPU constants to keep the example short. Vertex and index buffers are supported too, see [Vertex and index buffers](#vertex-and-index-buffers).

Next, configure a canvas and draw the three vertices:

```ts
const canvas = document.querySelector('canvas') as HTMLCanvasElement;
const context = root.configureContext({
  canvas,
  alphaMode: 'premultiplied',
});

pipeline.withColorAttachment({ view: context }).draw(3);
```

The fallback renders on an internal `OffscreenCanvas`, then transfers the result to the configured canvas. This requires support for `OffscreenCanvas`, WebGL 2, and the `bitmaprenderer` canvas context. Every draw recorded in one synchronous block of code (like a `requestAnimationFrame` callback) is presented as a single image, so passes that load the results of earlier passes (`loadOp: 'load'`) work as expected. Avoid awaiting anything between such passes, since that presents the earlier ones on their own. To skip the transfer altogether, [create the root with the canvas' own context](#initwithgl).

The `alphaMode` of `configureContext` isn't applied: whether the canvas is transparent depends on the `alpha` attribute of the WebGL context, which is on by default.

### Dynamic values

Uniforms are the supported way to pass values that change without recompiling the shaders. Create them with `root.createUniform`, reference them through `.$` in GPU code, and update them with `.write()`.

```diff lang=ts
+const time = root.createUniform(d.f32);

const pipeline = root.createRenderPipeline({
  vertex: ({ $vertexIndex: index }) => {
    'use gpu';
    return {
      $position: d.vec4f(positions.$[index], 0, 1),
      uv: uvs.$[index],
    };
  },
  fragment: ({ uv }) => {
    'use gpu';
-    return d.vec4f(uv, 0.5, 1);
+    return d.vec4f((uv + time.$) % 1, 0.5, 1);
  },
});
```

Then write the time before each draw:

```ts
function draw(timestamp: number) {
  time.write(timestamp * 0.001);
  pipeline.withColorAttachment({ view: context }).draw(3);
  requestAnimationFrame(draw);
}

requestAnimationFrame(draw);
```

### Textures

The fallback supports single-layer, single-sample 2D textures. A texture can be filled from the CPU, used as a render attachment, and sampled by another render pipeline:

```ts
const source = root
  .createTexture({ size: [2, 2], format: 'rgba8unorm' })
  .$usage('sampled');

source.write(
  new Uint8Array([
    255, 0, 0, 255, 0, 255, 0, 255,
    0, 0, 255, 255, 255, 255, 255, 255,
  ]),
);

const surface = root
  .createTexture({ size: [512, 512], format: 'rgba8unorm' })
  .$usage('render', 'sampled');

const surfaceTarget = surface.createView('render');
const surfaceTexture = surface.createView();
const sampler = root.createSampler({
  magFilter: 'nearest',
  minFilter: 'nearest',
});

// The pipeline target format must match the attached surface texture.
const firstPipeline = root.createRenderPipeline({
  vertex: fullscreenVertex,
  fragment: firstFragment,
  targets: { format: 'rgba8unorm' },
});

firstPipeline.withColorAttachment({ view: surfaceTarget }).draw(3);

const secondPipeline = root.createRenderPipeline({
  vertex: fullscreenVertex,
  fragment: ({ uv }) => {
    'use gpu';
    return std.textureSample(surfaceTexture.$, sampler.$, uv);
  },
});

secondPipeline.withColorAttachment({ view: context }).draw(3);
```

See the complete [Textures (WebGL fallback) example](/TypeGPU/examples/#example=simple--texture-gl), which uploads a small CPU-side palette, renders it into a surface texture, and samples that surface in a second pass.

The fallback normalizes WebGL's framebuffer texture orientation when a rendered texture is sampled, so the same UV coordinates produce the same orientation on the WebGL and WebGPU backends. CPU texture uploads keep their usual TypeGPU orientation.

Supported formats are `r8unorm`, `rg8unorm`, `rgba8unorm`, `rgba8unorm-srgb`, `rgba16float`, and `rgba32float`. Sampled views support `std.textureSample`, `std.textureSampleBias`, `std.textureSampleLevel`, `std.textureLoad`, and `std.textureDimensions`. Multisampled, layered, 1D/3D, depth, storage, and comparison textures remain unsupported.

### Vertex and index buffers

Buffers are created with `root.createBuffer`, like with WebGPU, and used through vertex layouts and index buffers:

```ts
const Vertex = d.struct({ position: d.vec3f, normal: d.vec3f });
const vertexLayout = tgpu.vertexLayout(d.arrayOf(Vertex));
const instanceLayout = tgpu.vertexLayout(d.arrayOf(d.vec4f), 'instance');

const vertices = root.createBuffer(vertexLayout.schemaForCount(24), meshVertices).$usage('vertex');
const offsets = root.createBuffer(instanceLayout.schemaForCount(100), instanceOffsets).$usage('vertex');
const indices = root.createBuffer(d.arrayOf(d.u32, 36), meshIndices).$usage('index');

const pipeline = root
  .createRenderPipeline({
    attribs: { ...vertexLayout.attrib, offset: instanceLayout.attrib },
    vertex: meshVertex,
    fragment: meshFragment,
  })
  .with(vertexLayout, vertices)
  .with(instanceLayout, offsets)
  .withIndexBuffer(indices);

pipeline.withColorAttachment({ view: context }).drawIndexed(36, 100);
```

A few differences from WebGPU come from WebGL 2 itself:

- A buffer can't have both the `'vertex'` and `'index'` usages, since WebGL 2 never lets a buffer that was bound as index data be bound as anything else. Create a separate buffer for each.
- A vertex layout's stride can be at most 255 bytes.
- Every vertex format is supported. `'unorm8x4-bgra'` attributes are reordered in the shader, since WebGL 2 can't read the BGRA order itself.
- A non-zero `firstInstance` (in `draw` and `drawIndexed`) or `baseVertex` (in `drawIndexed`) requires the `WEBGL_draw_instanced_base_vertex_base_instance` extension.
- Primitive restart is always enabled, even for list topologies, so the maximum index value (`0xFFFF` for `'uint16'`, `0xFFFFFFFF` for `'uint32'`) never refers to a vertex.

The fallback keeps a CPU-side copy of every buffer, and uploads what changed since the last draw that used it. That makes `read()`, `copyFrom()` and `clear()` simple CPU operations.

### Uniforms

Uniforms can hold any host-shareable data type: scalars, vectors, matrices, structs, and arrays of them (but not arrays of arrays, which GLSL ES 3.00 lacks). GLSL ES 3.00 has no half-precision uniforms either, so `f16` values are uploaded (and used in shaders) as 32-bit floats. They're created with `root.createUniform`, or with `buffer.as('uniform')` for buffers with the `'uniform'` usage, and uploaded before every draw that uses them, if they changed.

### Render state

Pipelines apply their `primitive` state (every topology, `cullMode` and `frontFace`), their targets' `blend` state and `writeMask`, and their `depthStencil` state (depth testing and writes, depth bias, and stencil operations, with the reference set by `withStencilReference`).

The blend constant keeps its default value of 0, as WebGPU only allows changing it on render passes, which the fallback doesn't have.

### Depth and stencil

Pass a depth attachment with `withDepthStencilAttachment`, like with WebGPU. Where the depth buffer comes from depends on the color target:

- When rendering into a texture, the view can be a depth texture created by the root (`depth16unorm`, `depth24plus`, `depth24plus-stencil8`, `depth32float` or `depth32float-stencil8`). Otherwise, the target texture gets its own depth-stencil buffer, which is shared by every pass that renders into it.
- When rendering into a canvas, the canvas' own depth (and stencil) buffer is always used, as nothing else can be attached to it, so passing a depth texture as the view throws. It's reset whenever the canvas is presented, so `depthLoadOp: 'load'` only carries the depth over between passes of one frame.

This means an app that only creates depth textures for WebGPU can pass any placeholder object as the view on the fallback:

```ts
import type { DepthStencilAttachment } from 'typegpu';
import { isGLRoot } from '@typegpu/gl';

const depthView = isGLRoot(root)
  ? ({} as DepthStencilAttachment['view'])
  : root.createTexture({ size, format: 'depth24plus' }).$usage('render');

pipeline
  .withColorAttachment({ view: context })
  .withDepthStencilAttachment({ view: depthView, depthLoadOp: 'clear', depthClearValue: 1 })
  .drawIndexed(indexCount);
```

Like in WebGPU, the depth and stencil load operations default to `'clear'` unless the aspect is read-only, the attachment's format has to match the pipeline's `depthStencil.format`, and stencil state requires a format with a stencil aspect.

Depth textures can't be written to from the CPU, or sampled with `texture_depth_2d` views.

### Multiple render targets

A fragment shader can return multiple outputs, each written into its own color attachment, matched by name. Every target can have its own blend state and write mask where the browser supports the `OES_draw_buffers_indexed` extension; otherwise, they all have to share the same ones. Rendering into a canvas and other attachments at once is not supported.

### Complete example

```ts twoslash
import { tgpu, d } from 'typegpu';
import { initWithGLFallback } from '@typegpu/gl';

const root = await initWithGLFallback();
const time = root.createUniform(d.f32);

const positions = tgpu.const(d.arrayOf(d.vec2f, 3), [
  d.vec2f(0, 0.5),
  d.vec2f(-0.5, -0.5),
  d.vec2f(0.5, -0.5),
]);

const uvs = tgpu.const(d.arrayOf(d.vec2f, 3), [
  d.vec2f(0.5, 1),
  d.vec2f(0, 0),
  d.vec2f(1, 0),
]);

const pipeline = root.createRenderPipeline({
  vertex: ({ $vertexIndex: index }) => {
    'use gpu';
    return {
      $position: d.vec4f(positions.$[index], 0, 1),
      uv: uvs.$[index],
    };
  },
  fragment: ({ uv }) => {
    'use gpu';
    return d.vec4f((uv + time.$) % 1, 0.5, 1);
  },
});

const canvas = document.querySelector('canvas') as HTMLCanvasElement;
const context = root.configureContext({
  canvas,
  alphaMode: 'premultiplied',
});

let animationFrame = 0;

function draw(timestamp: number) {
  time.write(timestamp * 0.001);
  pipeline.withColorAttachment({ view: context }).draw(3);
  animationFrame = requestAnimationFrame(draw);
}

animationFrame = requestAnimationFrame(draw);

function cleanup() {
  cancelAnimationFrame(animationFrame);
  root.destroy();
}
```

## Supported API

| Feature                                             | WebGL 2 fallback                                                                                              |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Vertex and fragment functions                       | Supported, including pipelines without a fragment function                                                    |
| TypeGPU constants and helper functions              | Supported                                                                                                     |
| Uniforms                                            | Supported for every host-shareable schema, except arrays of arrays (`f16` is uploaded as 32-bit floats)       |
| Vertex and index buffers                            | Supported (a buffer can't be both), with every vertex format and instancing                                   |
| Draws                                               | `draw` and `drawIndexed`, with `firstInstance` and `baseVertex` only where the browser supports them          |
| Primitive, blend and depth-stencil state            | Supported, except `unclippedDepth`, `depthBiasClamp` and dual-source blending                                 |
| Depth and stencil attachments                       | Depth textures, or an implicit depth buffer of the color target                                               |
| Multiple render targets                             | Supported, per-target blending needs `OES_draw_buffers_indexed`                                               |
| 2D textures and samplers                            | CPU uploads, color and depth attachments, sampling, and mipmap generation                                     |
| Multisampling                                       | Not supported (the canvas is antialiased by the browser)                                                      |
| Bind groups, readonly buffers, and mutable buffers  | Not supported                                                                                                 |
| Compute pipelines                                   | Not supported                                                                                                 |
| `console.log` in shaders                            | Not supported                                                                                                 |
| Command encoders, render passes and bundles         | Not supported                                                                                                 |
| Indirect draws                                      | Not supported                                                                                                 |

Unsupported operations throw a `WebGLFallbackUnsupportedError` (exported from `@typegpu/gl`), explaining that the operation is unavailable in the WebGL fallback. When you need different resource strategies for WebGPU and WebGL, use [`isGLRoot`](#isglroot) after initialization.

## Generating GLSL

The GLSL generator can also be used independently of the fallback root. Pass `glOptions()` to `tgpu.resolve` to resolve a TypeGPU function as GLSL instead of WGSL.

```ts twoslash
import { tgpu, d } from 'typegpu';
import { glOptions } from '@typegpu/gl';

const getColor = tgpu.fn(
  [d.vec2f],
  d.vec4f,
)((uv) => {
  'use gpu';
  return d.vec4f(uv, 0.5, 1);
});

const glsl = tgpu.resolve([getColor], glOptions());
```

For a vertex and fragment pair, use `dualGlOptions()`. Both stages share naming state, which keeps uniforms and inter-stage values consistent.

```ts
import { dualGlOptions } from '@typegpu/gl';

const options = dualGlOptions();
const vertexGlsl = tgpu.resolve([vertexFn, fragmentFn], options.vertex);
const fragmentGlsl = tgpu.resolve([vertexFn, fragmentFn], options.fragment);
```

:::note
`glOptions()` and `dualGlOptions()` use TypeGPU's experimental shader-generator option. Their returned option objects are intended to be passed directly to `tgpu.resolve` or `tgpu.resolveWithContext`.
:::

## API Reference

### initWithGLFallback

```ts
const root = await initWithGLFallback();
```

Attempts to initialize the standard WebGPU root first. If WebGPU is unavailable or initialization fails, it creates a WebGL 2 root using an internal `OffscreenCanvas`.

Use this function when WebGPU is preferred and the effect only relies on the [supported fallback API](#supported-api).

### initWithGL

```ts
const root = initWithGL();
```

Creates a WebGL 2 root without attempting WebGPU. This is useful for testing the fallback path or deliberately targeting WebGL 2.

You can provide an existing WebGL 2 context:

```ts
const offscreen = new OffscreenCanvas(1, 1);
const gl = offscreen.getContext('webgl2');

if (!gl) {
  throw new Error('WebGL 2 is unavailable');
}

const root = initWithGL({ gl });
```

Calling `initWithGL()` without an argument creates the offscreen canvas and context for you.

A context of an `HTMLCanvasElement` works too. The root then renders straight into that canvas, which the browser presents like any other WebGL canvas, skipping the copy from an offscreen canvas. In exchange, it's the only canvas the root can render into (the same goes for rendering into the root's own `OffscreenCanvas`):

```ts
const canvas = document.querySelector('canvas') as HTMLCanvasElement;
const gl = canvas.getContext('webgl2', { depth: true, stencil: true });

if (!gl) {
  throw new Error('WebGL 2 is unavailable');
}

const root = initWithGL({ gl });
const context = root.configureContext({ canvas });
```

Contexts created by the fallback have depth and stencil buffers. When providing your own, request them if you render into the canvas with a depth-stencil attachment.

The root also sets the context's provoking vertex to the first vertex of each primitive (through the `WEBGL_provoking_vertex` extension, where available), so that `flat` varyings match WGSL's.

### isGLRoot

```ts
if (isGLRoot(root)) {
  // Use a fallback-compatible resource strategy.
} else {
  // The root uses WebGPU.
}
```

Returns whether a root was created by the WebGL 2 backend. This is primarily useful after `initWithGLFallback()` when an application can use an optimized WebGPU path but still needs a fallback-compatible alternative.

### glOptions

```ts
const glsl = tgpu.resolve([resolvable], glOptions());
```

Returns resolution options that make TypeGPU generate GLSL for a single shader or helper-function graph.

### dualGlOptions

```ts
const options = dualGlOptions();

const vertexGlsl = tgpu.resolve([vertexFn], options.vertex);
const fragmentGlsl = tgpu.resolve([fragmentFn], options.fragment);
```

Returns separate vertex and fragment resolution options backed by shared cross-stage state. Create one options object per shader pair and use each side for its corresponding stage.
