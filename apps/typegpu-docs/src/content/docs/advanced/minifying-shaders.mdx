---
title: Minifying & Obfuscating Shaders
description: How to setup TypeGPU so that resulting shaders will be smaller or obfuscated.
---

:::caution[Experimental]
This feature is under development and is yet to reach stability.
:::

Regular JS minification & obfuscation does not alter the shader code generated by TypeGPU.
This is why we provide specific options for transforming shaders.

## Mangling variable names in plugin

`unplugin-typegpu` collects function metadata, which is later used for WGSL code generation.
With the `{ unstable_obfuscate: true }` option, all saved identifiers will be obfuscated:
- In the AST, all parameters and variables will have their names changed to `a`, `b`, `c`, ...
- Externals (the captured scope used by the function) will also have their respective identifiers changed.

:::note
It is required to disable the plugin auto-naming by setting `{ autoNamingEnabled: false }` for obfuscation to work. 
Only resources given name via `.$name()` will be named in the resulting shader.
:::

:::caution
Enabling obfuscation will also obfuscate error messages appearing during resolution.

It is not advised to obfuscate shaders during development.
:::

As an example, take a look at the following function:
```ts twoslash
import { tgpu, d } from 'typegpu';
// ---cut---
const coneVolume = tgpu.fn([d.f32, d.f32], d.f32)((radius, height) => {
  'use gpu';
  const baseArea = Math.PI * radius ** 2;
  const volume = (baseArea * height) / 3;
  return volume;
});
```

When obfuscated and resolved, it will look like this:
```wgsl
fn item(a: f32, b: f32) -> f32 {
  let c = (3.141592653589793f * pow(a, 2f));
  let e = ((c * b) / 3f);
  return e;
}
```

:::note
Obfuscation does not affect raw-WGSL implemented functions.
:::


## Removing whitespaces in runtime

Runtime minification removes all comments (possibly present in raw-WGSL implemented functions), and all redundant whitespaces.

To enable minification, set the `{ unstable_minify: true }` option in either `tgpu.resolve`, 
or in `tgpu.init` where it will act as a default for all rooted resolves.

:::note
`tgpu.init({ unstable_minify: true })` is not a global setting, as your application may use multiple roots.
For example, the following function will not be minified:
```ts twoslash
import { tgpu } from 'typegpu';
const root = await tgpu.init({ unstable_minify: true });

const fn = () => {
  'use gpu';
}

// The following resolve does not reference the root.
console.log(tgpu.resolve([fn])) // Not minified!
```
Resolves involving pipelines will inherit the root's setting.
:::

As an example, the `coneVolume` function would look like this when minified:
```wgsl
fn coneVolume(radius:f32,height:f32)->f32{let baseArea=(3.141592653589793f*pow(radius,2f));let volume=((baseArea*height)/3f);return volume;}
```

Of course, minification and obfuscation can be combined to achieve the following:
```wgsl
fn item(a:f32,b:f32)->f32{let c=(3.141592653589793f*pow(a,2f));let e=((c*b)/3f);return e;}
```
